**What the live tests changed in the design**
- **Billing:** you pay for the post text once per request, however many questions you ask. Going from 1 to 7 questions only added 73 input tokens, so asking for tags alongside the topic is nearly free.
- **Batching doesn't work at scale.** Packing many tweets into one request and asking about each one by position breaks down quickly:

  | Tweets per request | Accuracy |
  |---|---|
  | 8 | 8/8 |
  | 22 | 19/22 |
  | 44 | 28/44 |
  | 88 | 33/88 |

  Past about 20, even identical tweets got different labels. Sent one per request, they scored 22/22. So the code sends one tweet per request. Cost barely matters here: about $0.00003 per tweet.
- **Speed:** 32 requests with 8 at a time took 2.8 s in total. A typical request took 0.5 s and the slowest 0.96 s, with no rate-limit errors.
- **I dropped the `coherent` question.** It gives bad numbers: a clean sports cluster scored 0.26.
